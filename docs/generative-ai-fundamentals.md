# 생성형 AI, 기초부터 공부하기

수학 전공자가 아니어도, ML 경력이 없어도 따라올 수 있게 짠 12주 로드맵입니다.
순서가 핵심입니다. **"써보기 → 원리 → 응용 → 직접 만들기"** 순으로 가야 중간에 안 포기합니다.
거꾸로(수학부터) 시작하면 대부분 3주 안에 그만둡니다.

---

## 0. 전체 그림

| 단계 | 기간 | 목표 | 끝나면 할 수 있는 것 |
|---|---|---|---|
| 0. 준비물 | 1주 | Python + 실행 환경 | 코랩에서 코드 돌리기 |
| 1. 사용자로서 | 2주 | 프롬프트 + API | 내 업무를 LLM으로 자동화 |
| 2. 원리 | 4주 | Transformer가 뭔지 | "왜 이렇게 답하지?"를 설명 가능 |
| 3. 응용 | 4주 | RAG · 에이전트 · 평가 | 내 데이터로 챗봇 만들기 |
| 4. 심화 | 1주+ | 파인튜닝 · 멀티모달 | 원하는 방향 선택 |

시간이 없다면 **1단계 + 3단계만** 해도 실무에서는 대부분 통합니다.
2단계(원리)는 "왜"가 궁금해질 때 돌아와도 됩니다.

## 1단계 — 사용자로서 제대로 쓰기 (2주)

원리를 모르고 써도 됩니다. 오히려 여기서 생긴 의문이 2단계 공부의 연료가 됩니다.

### 알아야 할 개념 5개
- **토큰(token)**: 모델은 글자가 아니라 토큰 단위로 읽고 씁니다. 한국어는 영어보다 토큰을 많이 먹습니다. 비용·속도·길이 제한이 전부 여기서 결정됩니다.
- **컨텍스트 윈도우**: 한 번에 넣을 수 있는 최대 토큰 수. 대화가 길어지면 앞부분이 잘리거나 요약됩니다.
- **temperature / top-p**: 다음 토큰을 얼마나 과감하게 고를지. 낮으면 일관적·반복적, 높으면 창의적·불안정.
- **시스템 프롬프트**: 역할·규칙·출력 형식을 고정하는 자리. 매 요청마다 반복할 지시는 여기로.
- **환각(hallucination)**: 모르는 걸 모른다고 안 하고 그럴듯하게 지어내는 현상. 버그가 아니라 구조적 특성입니다 (2단계에서 왜인지 이해하게 됩니다).

### 프롬프트 기법 (효과 큰 순서대로)
1. **구체적으로 지시** — "요약해줘" ❌ / "3문장, 각 문장 40자 이내, 존댓말로 요약" ⭕
2. **예시 제공 (few-shot)** — 원하는 입출력 쌍 2~3개를 보여주는 게 설명 10줄보다 강력합니다.
3. **출력 형식 고정** — JSON 스키마, 마크다운 표 등. 후속 처리가 필요하면 필수.
4. **생각할 여유 주기** — "단계별로 근거를 먼저 쓰고 마지막에 결론" (복잡한 추론에서 정확도가 올라갑니다)
5. **역할·맥락 부여** — 독자가 누구인지, 어디에 쓸 글인지.
6. **제약을 부정형이 아니라 긍정형으로** — "짧게 쓰지 마" ❌ / "300자 이상 쓰기" ⭕

### 실습 과제
- [ ] 같은 질문을 temperature 0 / 1로 5번씩 돌려 결과 차이 관찰
- [ ] 내가 매주 반복하는 작업 1개를 프롬프트로 자동화 (회의록 정리, 메일 초안, 코드 리뷰 등)
- [ ] API로 "텍스트 → JSON" 추출기 만들기 (예: 뉴스 기사 → `{제목, 인물, 날짜, 요약}`)
- [ ] 같은 과제를 서로 다른 모델 2개로 돌려보고 차이 기록

## 2단계 — 원리 이해하기 (4주)

### 한 문장 요약
> **LLM은 "지금까지의 토큰들을 보고 다음 토큰의 확률분포를 내놓는 함수"이고, 그걸 반복 호출하는 것뿐입니다.**

이 문장이 완전히 이해되면 2단계는 끝난 겁니다. 환각도, temperature도, 컨텍스트 윈도우도 전부 여기서 파생됩니다.

### 2-1. 토크나이저 (3일)
- 문장 → 토큰 ID 배열로 바꾸는 규칙. **BPE(Byte Pair Encoding)** 가 표준.
- 왜 중요한가: 한국어 토큰 비효율, `strawberry`의 r 개수를 못 세는 이유, 숫자 계산이 약한 이유가 전부 토크나이저 탓입니다.
- 실습: 토크나이저 시각화 도구에 한국어/영어/코드를 넣고 토큰 수 비교.

### 2-2. 임베딩 (3일)
- 토큰/문장을 수백~수천 차원 벡터로 바꾼 것. **의미가 비슷하면 벡터가 가깝습니다.**
- 코사인 유사도로 "비슷함"을 계산 → 이게 3단계 RAG의 심장입니다.
- 실습: 문장 20개를 임베딩해서 유사도 행렬 출력 → 실제로 비슷한 것끼리 묶이는지 확인.

### 2-3. Transformer와 어텐션 (2주, 여기가 산)
- **어텐션**: 각 토큰이 "문장 안 다른 토큰들 중 누구를 얼마나 참고할지" 가중치를 계산하는 장치. `그것은`이 무엇을 가리키는지 찾아내는 원리입니다.
- **Q·K·V**: 질문(Query)을 던져 열쇠(Key)와 맞춰보고 값(Value)을 가져온다 — 딱 이 비유 수준으로 먼저 이해하고, 수식은 나중에.
- **멀티헤드**: 어텐션을 여러 개 병렬로 돌려 서로 다른 관계(문법, 지시, 주제)를 각각 포착.
- **위치 인코딩**: 어텐션 자체는 순서를 모르므로 위치 정보를 따로 주입.
- **디코더 전용 구조**: GPT·Claude 계열은 왼쪽→오른쪽으로만 보면서 다음 토큰을 예측.

> **공부 팁**: 논문(Attention Is All You Need)을 먼저 읽지 마세요. 영상으로 그림을 본 뒤 → 코드로 한 번 짜보고 → 마지막에 논문을 읽으면 30분이면 읽힙니다.

### 2-4. 모델은 어떻게 만들어지는가 (1주)
1. **사전학습(Pre-training)**: 인터넷 규모 텍스트로 "다음 토큰 맞히기"만 수천억 번. 지식과 언어능력이 여기서 생깁니다. (비용: 수백억 원대)
2. **지도 미세조정(SFT)**: 좋은 질문-답변 쌍으로 "비서처럼 대답하는 법"을 학습.
3. **정렬(RLHF / 선호 학습)**: 사람이 선호하는 답에 보상을 줘서 유용하고 안전한 쪽으로 조정.
4. **(최근) 추론 학습**: 정답이 검증 가능한 문제(수학·코드)로 "길게 생각하고 답하기"를 강화학습.

→ **환각이 왜 생기는지**가 여기서 풀립니다. 모델은 사실을 조회하는 게 아니라 **그럴듯한 다음 토큰을 생성**하도록 훈련됐기 때문입니다. "모른다"는 말은 학습 데이터에 드물고, 그럴듯한 답을 쓰면 보상을 받았으니까요.

### 2-5. 실습 (가장 중요)
직접 작은 GPT를 처음부터 짜보는 것 — 이거 하나가 영상 50개보다 낫습니다.
- 셰익스피어 텍스트로 문자 단위 GPT 학습 → 200줄 남짓 코드, 노트북에서도 돌아갑니다.
- 처음엔 이해 안 돼도 **따라 치면서** 진행하고, 두 번째에 안 보고 다시 짜보세요.

## 3단계 — 실제로 쓰이는 응용 (4주)

실무에서 하는 일의 90%는 여기 있습니다. 모델을 만드는 게 아니라 **모델을 조립**합니다.

### 3-1. RAG (검색 증강 생성) — 1.5주
내 문서를 모델에게 근거로 물려주는 기술. 사내 챗봇의 기본형입니다.

```
문서 → 청킹 → 임베딩 → 벡터DB 저장
질문 → 임베딩 → 유사한 청크 k개 검색 → 프롬프트에 붙여서 질문 → 답변 + 출처
```

- **청킹**: 문서를 자르는 단위(보통 300~800 토큰, 앞뒤 겹침). RAG 품질의 절반이 여기서 결정됩니다.
- **벡터DB**: 학습용은 FAISS나 Chroma로 충분. 처음부터 관리형 서비스 쓸 필요 없습니다.
- **하이브리드 검색**: 벡터 검색 + 키워드(BM25) 검색을 섞으면 대개 더 좋습니다. 고유명사·제품코드는 키워드가 강합니다.
- **리랭킹**: 20개 뽑아서 리랭커로 상위 5개만 남기기 → 정확도가 눈에 띄게 올라갑니다.
- **자주 겪는 실패**: 답이 틀렸을 때 원인이 (a) 검색이 잘못 가져왔는지 (b) 잘 가져왔는데 모델이 못 읽었는지 **반드시 분리해서** 보세요. 대부분 (a)입니다.

### 3-2. 도구 호출과 에이전트 — 1주
- **도구(함수) 호출**: 모델에게 함수 목록(이름·설명·파라미터 스키마)을 주면, 모델이 "이 함수를 이 인자로 부르자"는 JSON을 출력합니다. 실행은 **내 코드가** 합니다.
- **에이전트 루프**: `모델 호출 → 도구 실행 → 결과를 다시 모델에 전달 → 반복 → 최종 답변`. 개념은 이게 전부입니다.
- 프레임워크(LangChain, LlamaIndex 등)는 **직접 루프를 한 번 짜본 다음에** 쓰세요. 안 그러면 뭐가 돌아가는지 영원히 모릅니다.
- 실패 모드: 무한 루프, 도구 남용, 엉뚱한 인자. → 반복 횟수 제한과 로깅을 처음부터 넣으세요.

### 3-3. 평가(Eval) — 1주 ⭐ 가장 많이 건너뛰지만 가장 중요
- 프롬프트를 고쳤을 때 **좋아졌는지 나빠졌는지 측정할 방법이 없으면** 그냥 감으로 헤매는 겁니다.
- 최소 구성: **입력 20~50개 + 기대 결과**를 스프레드시트에 정리 → 바꿀 때마다 전부 돌려서 점수 비교.
- 채점 방법: 정답이 명확하면 문자열/정규식 비교, 애매하면 **LLM으로 채점(LLM-as-judge)** + 사람이 표본 검수.
- 로그를 남기세요. 어떤 입력에 어떤 프롬프트로 어떤 출력이 나왔는지.

### 3-4. 프롬프트 vs RAG vs 파인튜닝 — 선택 기준
| 문제 | 해법 |
|---|---|
| 형식·말투가 마음에 안 듦 | 프롬프트 (+ few-shot 예시) |
| 모델이 모르는 **사실**을 알아야 함 | **RAG** |
| 자주 바뀌는 데이터 | **RAG** (파인튜닝은 매번 다시 해야 함) |
| 아주 특수한 형식·문체를 매번 정확히 | 파인튜닝(LoRA) |
| 짧은 프롬프트로 비용·지연 줄이기 | 파인튜닝 |

→ **순서는 항상 프롬프트 → RAG → 파인튜닝.** 초보자가 가장 흔히 하는 실수가 파인튜닝부터 시도하는 겁니다.

### 3-5. 실무 감각 (0.5주)
- **비용·지연**: 토큰 수 × 단가. 긴 프롬프트가 반복되면 **프롬프트 캐싱**으로 크게 절감됩니다. 스트리밍은 체감 속도를 바꿉니다.
- **프롬프트 인젝션**: 외부 문서·웹페이지·사용자 입력에 "이전 지시를 무시하고 ~해라"가 숨어 있을 수 있습니다. **외부에서 온 텍스트는 명령이 아니라 데이터로 취급**하고, 권한이 큰 도구는 사람 확인을 거치게 설계하세요.
- **개인정보**: 외부 API에 무엇을 보내는지 항상 확인.

## 4단계 — 심화 (선택)

- **파인튜닝 / LoRA**: 적은 파라미터만 학습해서 저렴하게 조정. 데이터 수백~수천 건이 먼저 필요합니다.
- **로컬 모델**: Ollama 등으로 오픈 가중치 모델 실행. 양자화(quantization) 개념 필요.
- **이미지 생성 (디퓨전)**: 노이즈를 조금씩 걷어내며 이미지를 복원하도록 학습 → 텍스트 조건을 걸어 생성. Transformer와는 완전히 다른 계열이므로 별도 트랙으로 보세요.
- **음성·비디오·멀티모달**: 이미지/오디오를 토큰처럼 취급해 같은 Transformer에 넣는 방향.

## 흔한 함정 7가지

1. **수학부터 시작한다** → 90%가 포기합니다. 코드와 실습으로 시작하고 수학은 필요할 때 끌어오세요.
2. **영상만 본다** → 이해한 것 같지만 아무것도 못 만듭니다. 영상 1개당 실습 1개 규칙.
3. **프레임워크부터 배운다** → LangChain 튜토리얼은 잘 돌아가지만 고장 나면 손을 못 댑니다. 순수 API로 한 번 짜본 뒤에 쓰세요.
4. **파인튜닝이 만능이라 생각한다** → 대부분의 문제는 프롬프트나 RAG로 풀립니다.
5. **평가를 안 만든다** → 개선인지 개악인지 모른 채 프롬프트만 계속 고칩니다.
6. **최신 모델 소식만 쫓는다** → 근본 개념(토큰·어텐션·검색·평가)은 잘 안 변합니다. 거기에 시간을 쓰세요.
7. **혼자만 만든다** → 만든 걸 누군가 쓰게 하세요. 진짜 사용자 1명이 튜토리얼 10개보다 많이 가르쳐 줍니다.

## 프로젝트 아이디어 (난이도순)

1. **텍스트 → JSON 추출기**: 이력서/영수증/기사에서 구조화 데이터 뽑기 (1단계)
2. **개인 요약 봇**: 긴 문서·유튜브 자막을 내가 원하는 형식으로 요약 (1단계)
3. **문자 단위 GPT 직접 구현**: 좋아하는 텍스트로 학습시켜 문장 생성 (2단계)
4. **내 문서 Q&A 봇**: PDF 여러 개 넣고 출처와 함께 답변 (3단계 RAG)
5. **도구 쓰는 에이전트**: 검색 + 계산기 + 파일 읽기를 스스로 골라 쓰는 봇 (3단계)
6. **평가 파이프라인**: 위 프로젝트 중 하나에 테스트셋 30개 + 자동 채점 붙이기 (3단계) ← 이걸 한 사람이 진짜 드뭅니다
