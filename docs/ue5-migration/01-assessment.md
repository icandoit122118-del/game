# 01. 현황 조사와 범위 확정

이식은 "무엇을 가지고 있는가"를 정확히 세는 것에서 시작합니다. 이 단계를 건너뛰면
3단계쯤에서 예상치 못한 의존성(예: 전용 툴로만 만든 지형, 소스가 사라진 패키지)이
튀어나와 일정이 무너집니다.

## 1.1 UE2.5 프로젝트 파일 구조

전형적인 UE2.5(UT2004 기반) 설치 구조와 각 폴더의 의미입니다.

```
GameRoot/
  System/        *.u    컴파일된 UnrealScript 패키지
                 *.ini  설정 (Default.ini, User.ini, <Game>.ini)
                 *.int  로컬라이징 문자열
                 ucc.exe UnrealScript 컴파일러
  Maps/          *.ut2  레벨 (UE1 시절은 *.unr)
  Textures/      *.utx  텍스처 패키지
  StaticMeshes/  *.usx  스태틱 메시 패키지
  Animations/    *.ukx  스켈레탈 메시 + 애니메이션 패키지
  Sounds/        *.uax  사운드 패키지
  Music/         *.umx / *.ogg
  <MyMod>/Classes/*.uc  UnrealScript 소스 (있다면 최고의 자산)
```

> **`.uc` 소스가 남아 있는지 가장 먼저 확인하십시오.** `.u`만 있고 `.uc`가 없다면
> 게임 로직을 디컴파일(UTPT의 스크립트 뷰어 등)해서 읽어야 하며, 주석·변수명이
> 사라진 상태라 이식 비용이 2~3배로 뜁니다.

## 1.2 자산 인벤토리 만들기

아래 스크립트로 파일 수와 용량을 먼저 뽑아 규모를 파악합니다.

```bash
# 확장자별 파일 개수와 총 용량
find . -type f | sed 's/.*\.//' | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn

# UnrealScript 클래스 수와 총 라인 수 (이식 공수의 1차 지표)
find . -name '*.uc' | wc -l
find . -name '*.uc' -exec cat {} + | wc -l
```

그 다음 스프레드시트에 다음 표를 채웁니다. **"재사용 / 재제작 / 폐기"** 판정이
이 단계의 실제 산출물입니다.

| 항목 | 개수 | 용량 | 자체 제작 여부 | 판정 | 비고 |
|---|---|---|---|---|---|
| 맵 (`.ut2`) | | | | 재제작 | BSP 비중 높으면 전면 재작업 |
| 스태틱 메시 | | | | 재사용 | umodel 추출 → FBX |
| 스켈레탈 메시 | | | | 재사용 | psk/psa → 리타게팅 필요 |
| 텍스처 | | | | 재사용 | 해상도 낮으면 업스케일/재제작 검토 |
| 사운드 | | | | 재사용 | |
| UnrealScript 클래스 | | | | 재작성 | 전량 |
| 파티클/이펙트 | | | | 재제작 | Niagara로 전면 재작업 |
| UI (Canvas/GUI) | | | | 재제작 | UMG로 전면 재작업 |

## 1.3 공수 산정 기준선

경험적인 눈금입니다. 팀 규모와 원본 코드 품질에 따라 크게 흔들리므로 절대치가
아니라 **상대 비중**을 보는 용도로 쓰십시오.

| 작업 | 대략적 공수 |
|---|---|
| UnrealScript 1,000줄 이식 | 3~5 인일 (구조 재설계 포함) |
| 스태틱 메시 1개 추출·정리·임포트 | 0.1~0.3 인일 (배치 처리 시 급감) |
| 스켈레탈 캐릭터 1종 (메시+애님셋) | 3~10 인일 (리타게팅·본 정리 포함) |
| 중간 규모 멀티플레이 맵 1개 재구축 | 15~40 인일 |
| 파티클 이펙트 1종 Niagara 재제작 | 0.5~2 인일 |

**텍스처·메시·사운드는 자동화가 잘 되지만, 레벨과 스크립트는 사람이 다시
만들어야 합니다.** 전체 일정의 70% 이상이 이 두 항목에 몰린다고 보면 됩니다.

## 1.4 이식 범위 결정 (가장 중요한 의사결정)

다음 세 가지 중 하나를 명시적으로 골라 문서화하십시오. 중간에 바꾸면 비용이
가장 크게 새는 지점입니다.

1. **원작 재현 (1:1 포팅)** — 게임플레이 수치·레벨 레이아웃을 그대로 유지.
   UE5의 신기능은 최소한만 사용. 원작 팬층이 있는 프로젝트에 적합.
2. **리마스터** — 게임플레이는 유지하되 비주얼은 UE5 기준으로 상향(Lumen, Nanite,
   신규 텍스처). 가장 흔한 선택이며 비용도 가장 큼.
3. **리부트** — 원작 자산 일부만 참고하고 설계는 새로 함. 사실상 신규 개발.

범위 결정 후에는 **"UE5에서 다시 만드는 것이 더 싼 자산"** 목록을 따로 관리하십시오.
2004년 기준 512×512 텍스처나 800폴리 메시는 추출·정리하는 시간보다 새로 만드는
편이 저렴한 경우가 많습니다.
