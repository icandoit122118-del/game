# 10. 사례: 스플린터셀 카오스 시어리 → UE5 (취미 개발 기준)

이 문서는 **Splinter Cell: Chaos Theory (2005, Ubisoft Montreal)** 를 UE5로
옮기려는 개인 취미 프로젝트를 전제로 합니다. 앞선 00~09 문서는 "내 소스가 있는
UE2.5 프로젝트"를 가정하지만, 상용 출시작은 조건이 다르므로 그 차이를 먼저
정리합니다.

## 10.1 SC3는 순정 UE2.5가 아니다

SC3는 UE2.X를 Ubisoft가 상당히 개조한 브랜치 위에 만들어졌습니다. 2005년 기준
기술 쇼케이스에 가까웠고, UT2004류의 순정 UE2.5와는 다음이 다릅니다.

- 실시간 동적 그림자 중심 렌더링 (UE2.5의 라이트맵 베이크 문화와 반대)
- 노멀 매핑, SM3.0 경로의 패럴랙스·톤 매핑
- **빛 감지가 게임플레이 규칙인 구조** — 렌더링 결과가 곧 은신 판정
- 소음 전파/소음 미터
- 비대칭 멀티플레이 (Spies vs Mercs) — 진영별로 카메라·조작·감지 체계가 별개

즉 05 문서의 "BSP + 라이트맵 베이크" 전제가 SC3에는 부분적으로만 맞습니다.
반대로 **SC3의 동적 조명 설계는 UE5의 Lumen과 오히려 궁합이 좋습니다.**

## 10.2 결정적 차이: 게임 로직을 되찾을 수 없다

01 문서에서 "`.uc` 소스가 없으면 비용 2~3배"라고 했지만, 상용 출시작은 그
경우가 아닙니다.

- 게임플레이 로직의 상당 부분이 UnrealScript가 아니라 **Ubisoft가 작성한
  네이티브 C++ 바이너리** 안에 있습니다. 디컴파일로 복원할 수 있는 대상이 아닙니다.
- 따라서 이 작업은 **"이식"이 아니라 "관찰해서 재구현"** 입니다.
- 03 문서(UnrealScript → C++ 대응표)는 SC3에서는 거의 쓸 일이 없습니다.
  대신 05·06 문서(자산·물리·애니메이션)와 이 문서가 실제 작업 범위입니다.

### 수치를 실측하는 방법

재구현할 수치는 원작을 플레이하며 직접 재는 수밖에 없습니다. 취미 규모에서
실용적인 방법:

| 측정 대상 | 방법 |
|---|---|
| 라이트 미터 반응 곡선 | 광원에서 일정 거리씩 물러나며 미터 UI를 프레임 캡처 → 거리 대 값 그래프화 |
| 이동 속도 단계 | 고정 구간을 각 속도로 이동하며 프레임 수 측정 |
| 소음 반경 | 경비가 반응하는 지점까지의 거리를 반복 측정 (표면 종류별로) |
| AI 경계 단계 전이 | 발각 → 의심 → 복귀까지 걸리는 시간 측정 |
| 시야각·감지 거리 | 경비 정면에서 각도를 바꿔가며 발각 지점 기록 |

정확한 재현보다 **"느낌이 맞는가"** 가 취미 프로젝트의 합격선입니다. 소수점
둘째 자리를 맞추려 하지 마십시오.

## 10.3 법적 선 (취미 개발 전제)

개인 학습·모딩 목적으로 정품을 소유한 게임의 파일을 뜯어보는 것은 널리 이뤄지는
일입니다. 문제가 되는 지점은 명확합니다.

- ✅ **개인 PC에서 추출·학습·실험** — 배포하지 않으면 실질적 위험 없음
- ⚠️ **스크린샷/영상 공개** — 대체로 문제되지 않으나 "리메이크" 홍보는 눈에 띔
- ❌ **추출 자산이 포함된 빌드 배포** — Ubisoft 자산 재배포. 팬 리메이크가 실제로
  중단 통보를 받는 지점이 정확히 여기입니다
- ❌ **상업적 이용** — 논외

**권장**: 처음부터 자산을 "임시 참조물"로만 다루십시오. 원작 메시·텍스처는
`Content/Legacy/` 격리 구역에 두고 프로토타입에만 쓰다가, 나중에 Fab 무료
에셋이나 직접 만든 자산으로 교체하면 **공개 가능한 프로젝트**가 됩니다.
시스템 설계와 레벨 레이아웃은 저작물이 아니라 아이디어에 가까우므로, 그쪽에
투자한 시간은 그대로 남습니다.

## 10.4 자산 추출 — 먼저 확인할 것

SC3는 Ubisoft가 패키지 구조를 손봤을 수 있으므로, 일반 UT2004 절차를 그대로
가정하지 말고 **설치 폴더를 먼저 조사**하십시오.

```bash
# 설치 폴더에서 확장자별 파일 수 확인
find . -type f | sed 's/.*\.//' | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn | head -30

# 상위 용량 파일 (주요 데이터 컨테이너 파악)
find . -type f -size +20M -exec ls -lh {} + | sort -k5 -rh | head -20
```

그 다음 02 문서의 도구를 적용합니다.

- **UE Viewer (umodel)** — Splinter Cell 계열은 순정 UE2 패키지와 헤더가 달라
  **게임 오버라이드 옵션 지정이 필요할 수 있습니다.** umodel 실행 시 게임 선택
  UI에서 해당 타이틀을 지정하고, 자동 인식이 실패하면 커맨드라인 `-game=` 옵션을
  시도하십시오.
- 패키지가 열리지 않으면 커스텀 컨테이너일 가능성이 있습니다. 이 경우 해당
  게임 전용 모딩 커뮤니티의 도구를 찾는 편이 직접 포맷을 분석하는 것보다 빠릅니다.
- **스케일 보정**: 02 문서 2.5절의 ×2 규칙이 SC3에도 적용되는지는 **추출한 캐릭터
  메시 높이를 실측해 확인**하십시오. Ubisoft가 자체 스케일을 썼을 수 있으므로
  "샘 피셔 메시 높이 = 176cm"가 되도록 배율을 역산하는 것이 확실합니다.

레벨 지오메트리는 05 문서대로 **참조용으로만** 임포트하고, 정식 지오메트리는
UE5 Modeling Mode로 다시 만드는 것을 권합니다.

## 10.5 핵심 시스템 1 — 빛 감지 (프로젝트의 성패)

SC3의 정체성이자 UE5에 대응 기능이 **없는** 부분입니다. 엔진은 "이 지점의
밝기"를 게임플레이에 알려주지 않으므로 직접 구현해야 합니다.

### 구현 방식 비교

| 방식 | 원리 | 장점 | 단점 |
|---|---|---|---|
| **광원 직접 계산** (권장) | 레벨의 광원 목록을 관리하고, 플레이어 위치에서 거리 감쇠·스포트 콘·차폐 트레이스를 직접 계산 | 결정적, 서버에서 계산 가능, 디버깅 쉬움, 조명 파괴에 즉시 반응 | Lumen 간접광 미반영, 광원 수가 많으면 비용 |
| Scene Capture 리드백 | 플레이어 위치에 소형 SceneCapture를 두고 다운샘플해 평균 휘도 산출 | 실제 렌더링 결과 반영(간접광 포함) | GPU 리드백 지연, **데디케이티드 서버에는 렌더링이 없어 멀티플레이 불가** |
| 밝기 볼륨 베이크 | 레벨에 밝기 그리드를 사전 계산 | 런타임 비용 거의 0 | 동적 광원·조명 파괴 반영 불가 |

**SC3는 전구를 쏴서 끄는 것이 핵심 메커닉**이므로 정적 베이크는 탈락이고,
멀티플레이(Spies vs Mercs)까지 염두에 둔다면 **광원 직접 계산이 사실상 유일한
답**입니다.

### 설계 스케치

```cpp
// UStealthLightingSubsystem : UWorldSubsystem
//   - 레벨의 등록된 광원(ULightComponent) 목록을 유지
//   - 광원 on/off, 파괴 시 목록 갱신

// UExposureComponent : UActorComponent  (플레이어·AI 양쪽에 부착)
//   float ComputeExposure(const FVector& SampleLocation) const;
//     for each 등록 광원:
//       1. 감쇠 반경 밖이면 스킵
//       2. 스포트라이트면 콘 각도 판정
//       3. 광원 → 샘플 지점 라인 트레이스로 차폐 검사
//       4. 거리 감쇠 × 콘 감쇠 × 광원 강도를 누적
//     최종값을 0~1로 정규화
```

취미 규모에서의 실전 요령:

- **샘플 지점을 여러 개 두십시오.** 머리·몸통·발 3점을 재서 평균 내면
  "상체만 빛에 걸린" 상황이 자연스럽게 표현됩니다. 1점만 재면 판정이 딱딱합니다.
- **매 프레임 계산하지 마십시오.** 0.1초 간격이면 충분하고, 값은 보간해 미터가
  부드럽게 움직이게 합니다.
- **디버그 뷰를 먼저 만드십시오.** 화면에 현재 노출값과 기여 광원을 표시하는
  디버그 HUD가 있어야 튜닝이 가능합니다. 이걸 나중으로 미루면 감을 못 잡습니다.
- Lumen의 간접광은 이 계산에 잡히지 않습니다. 게임플레이상 "그림자인데 밝아
  보이는" 위화감이 크다면, 광원마다 간접광 기여분을 상수로 더하는 정도의
  근사로 충분합니다.

## 10.6 핵심 시스템 2 — 소음

| 요소 | UE5 구현 |
|---|---|
| 이동 속도별 소음 | `UCharacterMovementComponent::MaxWalkSpeed`를 연속 제어하고, 속도에 비례한 소음 강도 산출 |
| 표면별 소음 | `UPhysicalMaterial`을 확장해 표면별 소음 배율 보유 (카펫 0.3, 금속 1.5 등) |
| 소음 이벤트 발생 | `UAISense_Hearing::ReportNoiseEvent(World, Location, Loudness, Instigator)` |
| AI 청각 | `UAIPerceptionComponent` + `UAISense_Hearing` |
| 소음 미터 UI | 위 소음 강도를 그대로 HUD에 노출 |

기본 청각 감지는 **벽을 무시하는 단순 반경**입니다. SC3처럼 벽 뒤 소리가 줄어드는
느낌을 원한다면 두 가지 선택지가 있습니다.

1. 소음 발생 지점과 AI 사이에 라인 트레이스를 쏴서 차폐된 만큼 강도를 감쇠 (간단)
2. NavMesh 경로 거리(직선 거리가 아닌 실제 우회 거리)로 감쇠 계산 (정확하지만 비쌈)

취미 프로젝트라면 1번으로 시작하고, 부족하다고 느낄 때 2번을 검토하십시오.

## 10.7 핵심 시스템 3 — AI 경계 단계

UE5의 기본 시각 감지(`UAISense_Sight`)는 **밝기를 모릅니다.** 대상이 어둠 속에
있어도 시야에 들어오면 감지합니다. 두 가지 접근이 있습니다.

- **간단한 방법**: 기본 Sight를 쓰되, 플레이어의 노출값에 따라 `SightRadius`를
  런타임에 조절. 구현 30분, 대부분의 상황에서 그럴듯하게 동작합니다.
- **제대로 된 방법**: `UAISense` 파생 커스텀 감각을 만들어
  `노출값 × 거리 감쇠 × 시야각 × 차폐 × 이동 여부`로 **감지 게이지를 누적**.
  게이지가 임계값을 넘으면 단계 전이. SC3의 "서서히 들킨다"는 감각은 순간 판정이
  아니라 이 누적 구조에서 나옵니다.

경계 단계는 Behavior Tree 또는 State Tree + Blackboard로 구성합니다.

```
무경계 → (게이지 상승) → 의심: 하던 일 멈추고 쳐다봄
       → (계속 상승)   → 조사: 마지막 목격 지점으로 이동
       → (임계 돌파)   → 경계: 추적·수색, 동료 호출
       → (시야 확보)   → 교전
       → (일정 시간 미발견) → 하향 전이
```

**하향 전이를 반드시 넣으십시오.** 한 번 들키면 영원히 경계 상태인 AI는
스텔스 게임을 성립시키지 못합니다.

## 10.8 샘 피셔 이동·상호작용

| 원작 요소 | UE5 구현 방향 |
|---|---|
| 연속 속도 조절 (살금~달리기) | 아날로그 입력 → `MaxWalkSpeed` 연속 매핑 + 소음 연동 |
| 벽 붙기 / 모서리 엿보기 | 커스텀 이동 모드 또는 카메라 오프셋 + 몽타주 |
| 스플릿 점프, 파이프 매달리기, 난간 잡기 | Motion Warping + 애님 몽타주. **커스텀 이동 모드보다 몽타주 기반이 취미 규모에 훨씬 현실적** |
| 시체 운반 | 물리 액터를 소켓에 부착 + 이동 속도 페널티 |
| 나이트비전 / 서멀 / EMF | 포스트프로세스 머티리얼 3종을 전환. **구현이 쉽고 체감 효과가 커서 초반에 넣으면 동기부여에 좋음** |
| 문 천천히 열기 | 입력 유지 시간에 비례한 회전 + 속도에 따른 소음 |
| 자물쇠 따기, 광섬유 카메라 | 별도 UMG 미니게임 / SceneCapture 뷰 |

## 10.9 취미 프로젝트의 현실적 범위

**SC3 전체 이식은 개인이 끝낼 수 있는 규모가 아닙니다.** 원작은 수십 명이 몇 년
작업한 결과물입니다. 혼자서 끝을 보려면 범위를 이렇게 자르십시오.

### 목표: 한 구역, 한 경비, 한 루프

```
[1단계] 3인칭 캐릭터 + 속도 조절 이동          — 며칠
[2단계] 빛 감지 + 라이트 미터 디버그 표시       — 여기가 산. 충분히 시간을 쓸 것
[3단계] 방 하나 + 광원 몇 개 + 그림자 은신 성립  — 이때 처음 "게임"이 됨
[4단계] 경비 1명: 순찰 → 의심 → 조사 → 복귀     — 스텔스가 성립하는 순간
[5단계] 뒤에서 제압 + 시체 운반                 — 루프 완성
[6단계] 나이트비전 + 조명 파괴                  — SC 다움 완성
```

**6단계까지 도달하면 그것만으로도 완결된 프로토타입입니다.** 여기서 재미가
느껴지면 구역을 늘리고, 안 느껴지면 재미의 문제는 규모가 아니라 2·4단계 튜닝에
있으니 거기로 돌아가십시오.

### 취미 개발에서 흔한 함정

- **자산부터 추출하다 지치는 것** — 추출은 재미있지만 게임이 되지는 않습니다.
  2단계(빛 감지)를 UE5 기본 도형과 매네퀸만으로 먼저 만드십시오. 회색 박스로
  재미있으면 자산을 붙였을 때도 재미있고, 그 반대는 성립하지 않습니다.
- **레벨을 원작과 똑같이 만들려는 것** — 05 문서의 t3d 좌표 이관은 팀 프로젝트
